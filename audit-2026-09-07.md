# Additional implementation review — September 7, 2026

The additional review found and fixed three production issues in configuration handling and error reporting, plus one lab-helper lifecycle issue. No unresolved local implementation defect or missing version 1 feature was identified. The specification did not need a new design decision. Live SmarterMail and Windows Server verification remains pending.

## Fixed findings

| Finding | Effect before the fix | Resolution and verification |
|---|---|---|
| Ignored template annotations were strictly decoded | A valid first template token could fail startup because malformed UTF-8 appeared in a later, ignored note. | Template input alone now tolerates undecodable annotation bytes. The actual first token still must satisfy the ASCII address grammar; identity files remain strictly decoded. Six regression cases cover ignored bytes and invalid token bytes. |
| Stderr omitted child failure state | When trace and parent diagnostic output were unavailable, stderr could omit which child failed and where other child files remained. | Stderr includes the active child, attempted operation, source/destination, actual parent state, and every child status/path. Values remain quoted and control characters escaped. Tests block both file diagnostic destinations and verify the surviving stderr evidence. |
| Retained-copy errors could identify the wrong child | During `-keep` output copies, the active-child value still named the last constructed child, even when an earlier child's copy failed. | Update the active child before its copy operations. First-child and second-child collision tests verify correct stderr and parent diagnostics, unchanged existing evidence, and zero publication. The specified exclusion of keep copies from execution tracing is preserved. |
| A failed lab listener could leave a partial helper running | An unexpected TCP listener failure ended its accept loop while the helper process continued waiting for a console stop. | Listener failure now wakes the process owner, which cancels sessions and releases the remaining sockets. A real-socket self-test deliberately stops the SMTP listener and verifies notification, error accounting, and successful rebinding of all ports. |

The production changes are in [Configuration.cs](src/SmTagger.Engine/Configuration.cs) and [TaggerProcessor.cs](src/SmTagger.Engine/TaggerProcessor.cs). The separate lab changes are in [LabHost.cs](lab/SmTagger.LabServices/LabHost.cs) and [Program.cs](lab/SmTagger.LabServices/Program.cs).

## Verification gaps closed

The review checked the behavior against `spec.md`, the implementation guide, and the required test matrix. It added **48 test cases**, bringing the complete suite from 277 to **325**:

- Current and retired private-address matches at all 11 supported HDR/EML locations, including `Resent-Sender`, with exact output-byte checks for successful cases.
- Edited and synthesized folded continuation lines at exactly 998 and 999 bytes, counting indentation.
- A newly published mapping retained after header-length rejection, then reused after restart with allocation forbidden in the test and a shorter fresh message.
- Real child files that retain partial bytes after a simulated managed write failure or complete bytes after a simulated close failure; both HDR and EML cases verify no readiness/publication and successful later fresh mail.
- Seven deterministic process terminations spanning HDR ownership, staged/live mapping publication, child readiness, EML/HDR publication, all-child publication before cleanup, and the two From-error renames. Tests restart the production tagger watcher and verify exact retained inventories and hashes, complete mapping reload/reuse, no automatic replay, and successful fresh messages.
- Regression coverage for all three production fixes above.

The separate [crash worker](tests/SmTagger.CrashWorker/) exists only in the test build. Production executables expose no fault-selection arguments, environment variables, configuration, or message controls. No automatic recovery or deferred feature was added.
